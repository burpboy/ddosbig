# Protocol Implementation Details

## 1. General Principles
*   **Non-blocking I/O**: All sockets are set to `O_NONBLOCK`. If a send buffer is full, the socket is deregistered from epoll until it becomes writable again.
*   **Connection Multiplexing**: In `all` mode, multiple protocol handlers may share the same socket pool if configured, but typically separate sockets are used per protocol type to avoid head-of-line blocking.
*   **Spoofing**: Source IP spoofing is implemented at the IP header level. For TCP/UDP, the checksum must be recalculated after modifying the source IP.

## 2. TCP SYN Flood (`SynFlood`)
*   **Mechanism**: Sends TCP segments with `SYN` flag set.
*   **Headers**:
    *   IP Header: Source IP is randomized (unless spoofing is disabled). TTL is randomized between 10-255.
    *   TCP Header: Source Port is randomized. Sequence Number is random. Ack Number is 0. Flags = `0x02` (SYN). Window Size is small to encourage the target to allocate resources for the half-open connection.
*   **Checksum Calculation**: Must compute both IP Header Checksum and TCP Pseudo-Header Checksum accurately. Errors result in dropped packets by the target kernel.
*   **Rate Control**: Enforced via Token Bucket Algorithm using `Timer`.

## 3. UDP Flood (`UdpFlood`)
*   **Mechanism**: Sends raw UDP datagrams with large payloads.
*   **Payload**: Random bytes generated by `RandomUtils`. Size is determined by `--payload-size`.
*   **Bandwidth Limiting**:
    *   Calculates bytes sent per second.
    *   If `--udp-bandwidth` is exceeded, the thread sleeps briefly or reduces send frequency.
*   **Port Handling**: Destination port is fixed (`-p`). Source port is ephemeral (random) for each packet or connection group.

## 4. HTTP Flood (`HttpFlood`)
*   **Mode**: Supports GET and POST.
*   **GET Request**:
    ```http
    GET / HTTP/1.1\r\n
    Host: <target_domain>\r\n
    User-Agent: Mozilla/5.0... [Randomized]\r\n
    Accept: text/html,application/xhtml+xml...\r\n
    Connection: keep-alive\r\n
    \r\n
    ```
*   **POST Request**:
    *   Body size is controlled by `--payload-size`.
    *   Content-Type: `application/x-www-form-urlencoded` or `multipart/form-data`.
    *   Headers include dynamic `Content-Length`.
*   **Keep-Alive**: Connections are reused until the server closes them or a maximum request count per connection is reached. This reduces overhead compared to opening/closing sockets for every request.
*   **Jitter**: Random delays between requests per connection to simulate human-like behavior.

## 5. DNS/NTP Amplification (Modules)
*   **DNS Amplification**:
    *   Sends small DNS queries (e.g., ANY record) to open resolvers (if list provided) or directly to target if targeting DNS service.
    *   Exploits response size multiplier (up to 50x-100x).
*   **NTP Amplification**:
    *   Sends `MONLIST` or `README` commands to NTP servers.
    *   Similar amplification factor.

## 6. Error Handling & Recovery
*   **Socket Errors**: If `ECONNRESET` or `EPIPE` occurs, the socket is removed from the active set and destroyed.
*   **Resource Exhaustion**: If `EMFILE` (too many open files) occurs, the thread pauses and retries after a short delay.
*   **Graceful Degradation**: If one protocol fails (e.g., DNS port blocked), other protocols continue unaffected.
